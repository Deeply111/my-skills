# 交之前：自评、独立审片、复盘

吸收自 concept-short（skill-v4）的 `模板/自评.md`、`模板/审片人说明.md`、`记录/复盘.md`。检查全过只说明没有技术毛病，不说明好看。

## 一、自评（每次交给用户之前写，存进本期 `自评.md`）

先切回导演身份，按第一次在手机上刷到的观众完整看一遍（出了片就实时放，一遍关声音、一遍开声音；只有抽帧时说明只看了帧）。写不出来就不交；看出来能改的先改。

```
# 自评：<本期> · <交的是什么：动作表 / 抽帧 / 前一段成品 / 成片>

1. 好看：哪几帧能当封面，哪几帧不能、为什么；哪个动作的曲线、分量、停顿不舒服
2. 停下来：开头 2 秒凭什么让人停下来
3. 看得懂：每个比喻看不看得出；哪一句是贴上去的、全靠字幕的
4. 有感觉：哪一处心里一沉；哪一段平
5. 带走一个画面：看完记住的是哪个
取舍：哪样手法说不出服务上面哪一条，去掉了没有

最差的三处：在哪（行号/秒）、问题、改了没有，没改的为什么
预测用户会怎么说：最可能挑的毛病，猜一句原话
```

## 二、独立审片（长片、成片时做一轮；13 秒这类片段可以只自评）

准备审片包：接触表（每 0.5 秒一格，`snapshot --at` 生成）、字幕表（每句文字和时间，从 `data/caps.js` 抄）、声音表（第几秒听到什么）。**不给动作表和意图。**

派一个没参与过的 agent，分两次给：

**第一次只给前 3 秒**（每 0.25 秒一张）：

> 你第一次在手机上刷到这条横屏口播短片，只看一遍，不会暂停，两三秒不对就划走。你没参与制作。这是前 3 秒，你会停下来接着看还是划走？为什么？一两句话。

**它答完再给全片**：

> 接触表是全片每 0.5 秒一张，字幕表是他说的每句话和时间，声音表写了第几秒听到什么。你看不到动作流不流畅，不用评价动作。按顺序答：
> 1. 这一段在讲什么？一句话。记住了哪个画面？
> 2. 哪几处想多看一眼，哪几处难看、乱、廉价？
> 3. 画面里的东西在比喻什么，哪些一眼看懂，哪些没看懂或像硬贴上去的？
> 4. 按时间点列问题，分两档：一定会划走 / 看不懂；有点别扭（拖、重复、乱、字和画打架）。只说问题，不写怎么改。
> 5. 有没有一处让你心里一动？会不会转发？
> 没问题的地方不写，不凑数，不客气。

**审完**：结论原样保留；逐条判断是真问题还是故意的，真问题改，故意的写一句理由。一个问题查一类：把所有行里同类的地方一起修。"看不懂"改完，再派一个新审片人只看那几秒。

## 三、交给用户时说清

- 文件路径；哪些只看了抽帧、没完整看过听过。
- 自评里最差的三处和处理。
- 请用户在手机上按真速、开声音看一遍，再关声音看一遍：错字、一闪的穿帮、声音不对，靠这一遍。

## 四、复盘（每期交付后）

在本期目录写 `复盘.md`：用户每次提的意见（照抄原话）、根子出在哪一步（原本打算怎样、实际怎样、为什么有差别）、下次要重复的三件事、不要再做的三件事。写成判断标准，不写这一期的具体现象。

值得改 skill 的，列成表交给用户（改哪里 | 怎么改 | 为什么），**点头才改**。加一条规矩时同时写出能删掉哪条。
