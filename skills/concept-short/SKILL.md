# 文案做成动画短片

**宗旨**：做出用户轻松看、爱看、想不停地看，同时又有收获和启发的动画。所有技术和手法只为五件事，有先后：

1. **好看**（前提）：画面好看——随便截一帧都舒服；动画好看——动起来也舒服（`参考/动作.md` 的表）。
2. **停下来**：刷到时不划走。
3. **看得懂**：一眼明白，不费力。
4. **有感觉**：心里一沉、一紧。
5. **带走一个画面**：过几天还记得。

**取舍标准**：每加一样技术或手法，先问它服务五条里的哪一条，答不上来就不加；加了不让画面或动画更好看、也不服务其他四条的，就减掉。好看往往来自减法。流程和检查都是手段：检查全过不等于做好了；某条规矩和宗旨冲突时以宗旨为准，交的时候说明破了哪条、为什么。

**输入**：用户给的文案。里面可能混着上屏的字幕和给助手看的描述，第 1 步先分清；字幕不改说法。
**配乐**：固定用「若如初见」，从头开始放；`音乐/` 里有原速、0.9、0.8 倍速三版，第 1 步选（`参考/配乐.md`）。
**输出**：横屏 1920×1080、30 帧（`片子.json` 写 `"画幅": "竖"` 出 1080×1920），码率不超过 12M。
**字幕**：默认宋体，换画风后真不搭时先问用户；进入世界的字可以用片内字体；字号、安全区、位置按画幅（`参考/字幕.md`）。

## 流程

| 步 | 做什么 | 产出 | 拍板 |
|---|---|---|---|
| 0 音乐地图 | 只做一次，所有片共用 | `音乐/` | |
| 1 画面卡 | 读文案；写看下去的理由、主线比喻；逐句写卡（比喻从哪长出来、3D/2D、镜头）；排时间轴；冷读测试 | `画面卡.md`、`代码/时间轴.json` | |
| 2 样张 | 主方向 3 张样张 + 另一方向 1 张对照帧；色板和色条；主体（3D 的建好模） | `样张/`、`代码/色板.js`、`画风/` | **① 方向** |
| 3 前 20 秒 | 按时间轴从头直接精做前 20 秒，就是成片质量 | `草稿/前20秒.mp4` | **② 前 20 秒** |
| 4 成片 | 照前 20 秒的标准做完全片；机器检查；一轮独立审片 | `<片名>.mp4` | **③ 成片** |
| 5 回流 | 复盘；改 skill 先列方案 | `记录/` | 改 skill 前请示 |

每一步怎么做读 `步骤/` 下对应的文档；技术细节在 `参考/`（字幕、镜头、动作、比喻、质感、3D、音效、配乐、检查、画风模板），用到哪个读哪个。

**"直接做"模式**：用户说"别问我，直接做"时，在 `片子.json` 写 `"模式": "直接做"`：①②不停下来等，样张和前 20 秒照做、照存、照样自查，直接交③成片，交片时附上它们的路径。

**每个镜头只写一版**（`final`），一开始就是成片质感（旧片子的 `board`/`final` 两版照样能渲）。3D 镜头写 `三维:`，2D 叠加写 `final`。

## 3D 和 2D

3D 层每条片都加载（`引擎/3d.js`，three.js），按元素选：**空间、光、材质、穿过空间的运镜、有体积的比喻、站在场景里的人物用 3D；字、比喻线、UI、风格化的形象、细碎粒子用 2D**，大多数镜头是"3D 做空间、2D 叠字和线"。只有整条片的画风本身是纯平面时才整片不用 3D，第 2 步说明为什么。分工表和工具见 `参考/3D.md`；人物在 Blender 里建模、烘阴影（`脚本/blender/`）。

## 规矩

1. **拍板点之前不往下走**（"直接做"模式除外）。用户明确同意了才记确认，照抄原话。
2. **有人物时，脸只有两种画法**：不画五官，或者画符号化的脸。不画写实的脸。同一条片里所有人物用同一种画法。
3. **交给用户之前，切回导演身份。** 按第一次刷到的观众的眼光完整看一遍（视频就实时放），按五条目的问自己，写最差的三处、预测用户会怎么说（`模板/自评.md`）。写不出来就不能交。
4. **给用户看的图由脚本生成**，不挑好看的。
5. **拍板点之外不找用户**，除非要打破用户定过的规矩，比如改配乐、画风、字体。
6. **改 skill 先请示。** 要改哪些、怎么改、为什么，列成方案给用户，点头才改。
7. **用户要求返工时，先好好想这个地方应该达到怎样的效果**：意图是什么，要给观众什么感受和情绪。想清楚了再动手。
8. **画风只建在片子里。** 画笔、主体、物件、运动规范、3D 布景和模型都放 `片子/<片名>/画风/`。skill 的 `画风/` 是画风模板目录（现在是空的），往里写任何东西先问用户（`参考/画风模板.md`）。
9. **比喻从场景里长出来。** 每张卡要有一个比喻元素把这句话演出来，而且它是从场景里已有的东西（人、光、地面、道具）长出来的，不是贴上去的（`参考/比喻.md`）。
10. **音效素材守授权。** 人物动作来自 Mixamo（`素材/动作/`），不是 CC0：交片时说明来源，授权以 Adobe 的条款为准。 BBC 音效库只能个人、教育、研究用途，不能商用：用了它的片子交片时说明"含 BBC 素材，不可商用"；Freesound 只用 CC0。出处由 `脚本/素材.py` 自动记。3D 的材质、HDRI、模型只用 Poly Haven、ambientCG 的（CC0），由 `脚本/三维素材.py` 下载并记出处。

## 省时间、省 token（不拿质量换）

- **少渲**：改动攒一批再渲，先抽静帧确认；能看静帧就不渲视频。用户指出问题后，只渲那一段给用户看（前后带一点，十来秒）。显卡渲染：60 秒 1080p 带全部检查约 10–15 分钟。
- **3D 先算好再渲**：3D 只在画风需要时用；调机位先出单张静帧，把人、比喻元素和字幕的位置算好、画幅定死再渲视频。
- **看图**：看接触表，拿不准再裁局部、看原图。
- **读和改**：只读要改的镜头文件和当前这步、要用的参考文档；读过没变的不重复读；改代码用小范围修改。
- **agent 只派三处**：冷读测试、成片审片、"看不懂"的复查。不派更便宜的模型。

## 回流（每条片交付后）

写进 `记录/复盘.md`，一条片一段：每个拍板点上用户提了哪些意见、根子出在哪一步（原本打算怎样、实际怎样、为什么有差别）；下次要重复的三件事、不要再做的三件事。挖出来的原因写成判断标准，不写这条片的具体现象。值得改 skill 的，列成表交给用户（改哪里 | 怎么改 | 为什么），批准后再改，改完在 `CHANGELOG.md` 记一行。加一条规矩时同时写出能删掉哪条；几条片都没拦住过任何问题的规矩，提议删掉。
