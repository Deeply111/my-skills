# 配色规则

数据在 `palettes.json`（唯一数据源）。抽色和校验都走 `../scripts/pick_palette.py`。
**不要凭感觉手挑颜色**，也不要直接改这份 md 里的色值 —— 改 `palettes.json`，然后跑 `--audit`。

## 三元组模型

一组封面配色不是"两个撞色"，是**三个角色一起成立**：

| 角色 | 承担什么 | 面积 |
|---|---|---|
| **BG 底色** | 暖米白纸底 | 100% |
| **INK 主色** | 标题里非钩子的部分、副标题、kicker、人物描边 | 大 |
| **POP 撞色** | 钩子词（可整行）、下划线、色块 banner、火花、人物外圈虚线 | **约 20–35%，不超过 INK** |
| `INK2`（可选） | 标题第二行换个深色，制造层次 | 中 |
| `assist`（可选） | 浅色装饰块、背景形状 —— **禁止用于任何文字** | 小 |

## 一条硬规矩

> **亮色只做点，不做面；饱和度不能太低，但要有节制。**

翻译成参数：
- POP 饱和度 **≥ 0.55**（低于这个值就是灰的，撞不起来）
- POP 面积 **约 20–35%，不超过 INK**（可以整行撞色）
- INK 明度 **L\* ≤ 45**（要够深，才压得住大面积文字）

参照效果最好的一张：亮黄只落在钩子词三个字和一条下划线上，其余全是深藏青。

## 校验用的是感知色差，不是 WCAG

**这一条很关键，别改回去。**

如果用 WCAG 亮度对比度做校验，会把 5 张实战封面全判为不合格 ——
因为「米白底上的巨幅亮黄毛刷字」亮度差极小（对比度只有 1.67），WCAG 认为不可读。
但它恰恰是点击率最好的封面之一：**封面标题是巨字，靠的是彩度撞击，不是亮度对比。**

所以改用 **CIE Lab ΔE 感知色差**，阈值直接取自那 5 张实战封面的实测下界：

| 指标 | 阈值 | 实战下界 |
|---|---|---|
| ΔE(INK, BG) | ≥ 55 | 59.0 |
| ΔE(POP, BG) | ≥ 52 | 58.7 |
| ΔE(INK, POP) | ≥ 55 | 62.1 |
| POP 饱和度 | ≥ 0.55 | 0.66 |
| INK 明度 L\* | ≤ 45 | 41.0 |
| L\*(POP) − L\*(INK) | ≥ 12 | 14.8 |

新增色卡后**必须**跑一次：

```bash
python3 scripts/pick_palette.py --audit
```

## 两个流派

| 流派 | 用在什么选题 | 组数 |
|---|---|---|
| **重击派** | 教程 / 工具 / 结论型 —— 要缩略图点击率 | 11（全部实战验证过） |
| **高级派** | 思考 / 观点 / 人文叙事 / 女性成长 —— 要调性 | 7 |

每期只用一组色，默认从重击派里挑。
用户说"这期要高级点"就 `--family 高级派`，说"要冲点击"就 `--family 重击派`。

## 顺色规则

每组色卡都标了 `wardrobe`（顺色的衣服颜色）。抽色前先看当期人物照的衣服主色，
用 `--wardrobe 灰绿` 过滤。**衣服颜色要跟 INK/POP 处在同一个温度带，不能打架。**

如果衣服颜色不在任何色卡的 wardrobe 里，脚本会退回全池并警告 —— 这时要人工看一眼。

## 不能当 POP 的颜色

这几个太浅，对暖米底色差不足，**只能做 assist（浅色块 / 装饰形状），
不能当钩子词**，否则缩略图上直接糊掉：

`#9EB1D1 SKY` · `#D1C5CB CLOUD` · `#E0B1A0 DUSK` · `#E8DDD1 SAND` ·
`#BA867D` · `#9AABB3` · `#989B84 MOSS`

## 防撞脸

每期定稿后记一笔，下 4 期会自动避开这组色：

```bash
python3 scripts/pick_palette.py --commit navy-amber --slug 20260827_视频动效
```

历史写在 `used.json`（首次运行时自动创建）。

## 加新色卡

1. 编辑 `palettes.json`，按现有 schema 加一条（`family` 填 重击派 / 高级派）
2. 跑 `--audit`，不通过就调色值直到通过
3. `wardrobe` 一定要填，否则顺色过滤用不上它
